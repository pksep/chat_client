# Code Comments Policy

## General Guidelines

When working on code in this project:

1. **Minimize comments**:
   - Code should be self-explanatory through good naming conventions
   - Avoid obvious comments that just restate what the code does
   - Use comments only when necessary to explain the "why" not the "what"

2. **Focus on complex logic**:
   - Add comments only for complex business logic that isn't immediately obvious
   - Explain reasoning behind non-standard implementations
   - Document workarounds and temporary solutions

3. **Code documentation**:
   - Use proper function and class documentation where appropriate
   - Follow existing project standards for API documentation
   - Prioritize clean, readable code over commented code

4. **Avoid redundant comments**:
   - Don't add comments that just repeat what the code says
   - Don't write comments to explain basic programming concepts
   - Remove commented-out code blocks
