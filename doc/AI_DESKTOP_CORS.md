# Каталог ИИ: источники веба и Tauri

26.11.2026 production `/response-models` вернул preflight 204 с разрешением
`https://chat.pksep.ru`, но без `Access-Control-Allow-Origin` для
`http://localhost:5173`, `http://tauri.localhost`, `https://tauri.localhost`,
`tauri://localhost`. В Chrome зафиксирован `PreflightMissingAllowOriginHeader`.
Авторизация `/api/users/me/access` при этом успешна. Различие версий клиента
не устраняет этот отказ: источник запроса отличается.

В chat_ai подготовлена общая политика `createAiServerCors` поверх существующего
`parseAllowedOrigins(process.env.ALLOWED_ORIGINS)`. При выкладке нужно сохранить существующий JSON-массив и добавить точные
источники установщиков: `http://tauri.localhost`, `https://tauri.localhost`,
`tauri://localhost`. `*` не нужен. Для разработки используется opt-in прокси ниже,
без добавления произвольных localhost-портов в production.
Проверка JWT, персональных прав, MCP и бизнес-операций остаётся прежней.
Production-настройка в рамках локальной проверки не изменена.

Для проверки исходников до выкладки AI-сервера предусмотрен opt-in
`VITE_CHAT_AI_DEV_PROXY_TARGET=https://chat-server-prod.pksep.ru`.
Vite проксирует `/__chat-ai` в указанный сервер; все ИИ-вызовы используют
его через общий `getConfig`. Совпадение upstream проверяется, raw-конфиг
не переписывается в хранилище, cookies не передаются. Bearer и серверная
проверка доступа сохраняются. Преобразование действует только в DEV и на
loopback-адресе, в production/Tauri-пакет не попадает.

Локальный прокси подтверждает работу клиента с настоящим API, но не заменяет
разрешение источников установленного приложения на AI-сервере. До этого
нельзя объявлять исправленным production-Tauri только по локальному успеху.

## Проверки 26.11.2026

- В локальном полном клиенте получен настоящий `/response-models` и ответ
  «Работает.» на синтетический запрос. Пользователь подтвердил появление моделей
  в локальном Tauri.
- TypeScript, ESLint, production-сборка клиента и unit-проверки прокси прошли.
- Восемь E2E выбора моделей прошли на desktop/mobile и в обеих темах.
  Полный сценарий активности агента и отдельный сценарий выбора папки прошли.
  Старый тест обновлён под общий компонент ИИ и доступный до выбора папки каталог;
  чтение результата асинхронного native reveal теперь ожидает завершения IPC.
- Сервер: 14 регрессий CORS и всего 1401 тест прошли с двумя workers. Первый
  неограниченный параллельный прогон имел один timeout crash-теста; ожидания не менялись.
- На собственном HTTP-сервере с настоящей авторизацией проверены три origin:
  preflight, каталог с JWT/grant, отказ анонимному и постороннему origin,
  генерация с CORS-заголовками, сохранение результата и смена провайдера.
- Сборка AI `build:check` прошла повторно после отказа resolver зависимости
  `posthog-node`; встроенная генерация необязательного package-lock завершилась
  предупреждением. Запуск Windows-сборки AI отдельно не прошёл: generated output
  содержит обратные слэши в импорте `@modelcontextprotocol/sdk`. Это не пакет
  Tauri и не проверка production Linux. Этот дефект упаковки здесь не менялся.
- Полный `verify:local` AI не прошёл: локальные сервисы AI/ERP не запущены,
  отсутствует настройка источника вложений, старый локальный профиль модели не
  соответствует каталогу. Это не результат проверки production.
- Денис применил три origin и перезапустил только `chat-ai` 26.11 в 16:58
  (Asia/Yerevan). Независимый production HTTP-check прошёл: preflight каталога и
  генерации для трёх origin, защищённый отказ без JWT с корректным CORS, отказ
  постороннему и `null` origin. Денис отдельно подтвердил 200 и 20 моделей с
  авторизацией для каждого origin, сохранность истории и остальных сервисов.
  Исходник также слит в [chat_ai #20](https://github.com/pksep/chat_ai/pull/20).
  Старый GitHub-деплой `chat_ai` пока не запускается: шаблон требует непереданный
  `ALLOW_REPOS`, доступных self-hosted runner нет. Эта настройка применена DevOps.

`desktop_agent_models` остаётся IPC локального агента. Выбор папки доступен
во вкладке «Агенты» и требует отдельной настройки подключения агента.
Нельзя подменять его каталог серверным списком обычного ИИ-чата:
это не предоставит агенту доступа к модели. Провайдерский ключ в установщик не входит.
