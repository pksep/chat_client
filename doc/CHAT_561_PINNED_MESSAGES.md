## Реализация

Синяя кнопка перед X открывает отдельный слой списка. Её событие не доходит до
перехода/открепления. Список показывает кеш сразу, сортирует по времени оригинала,
разделяет даты, использует существующие компоненты текста/медиа/файлов/стикеров
и значок pin у времени. Первые 80 элементов монтируются сразу, следующие —
порциями по кнопке. Поля отправки нет. Текст переводит к оригиналу, вложения
открывают прежний просмотр, стикер сохраняет действие открытия набора.

Переписка остаётся смонтированной под списком: сохраняются редактор, черновик
и viewport anchor. Под списком блокируются pointer/keyboard через `inert`,
read сообщений/реакций, фоновые проверки пагинации и автопрокрутки; строки
заморожены, arrival/deletion и sticker-анимации приостановлены. После возврата
восстанавливаются observers и якорь. Вставка выше viewport может изменить
числовой scrollTop: видимый оригинал остаётся на том же месте экрана.

Заметка — отдельная карточка с линией, автором, текстом и датой, под оригиналом
в переписке и списке. Desktop использует кнопки edit/X, mobile — компактные
действия по нажатию своей карточки. Собственность проверяется в UI и очереди.
Удаление заметки сохраняет закрепление.

GET `/messages/topic/:topicId/pin-comments`, POST того же пути `/commands`.
Непустой текст и PIN отправляются одной командой. Пустой текст использует прежний
pin. `revision` остаётся строкой; UUID создаётся `crypto.randomUUID()`.
На 404/405 GET поле видно, но отключено: обычное закрепление работает.
Локальная общая заметка вместо отсутствующего API не создаётся.

Очередь и снимок находятся в штатной `chat-topic-messages-db` (7 вместо 6),
в новом store `pinCommentTopics`, с ключом сервера/владельца/топика. Миграция
и версии pending-upload worker/service worker согласованы. Старая история,
закрепления и незавершённые загрузки сохраняются.

Команда сохраняется до сети, повтор/перезапуск использует тот же payload/UUID.
ACK сверяет идентичность, scope, оригинал, сессию и строковую revision, заменяет
оптимистическое состояние без дубля. Epoch/request guards блокируют запоздалые
GET, hydrate и ответы прежнего владельца. Отсутствующий в памяти оригинал после
перезапуска проверяется через существующий around, tombstone запрещает отправку.
409 обновляет подтверждённые pins/notes и оставляет текст для копирования.
Старая toggle-команда автоматически не переигрывается. Пока новая команда не
подтверждена, конфликтующие pin/notes исходного сообщения заблокированы.
SELF фильтруется по владельцу. Unpin скрывает заметки, repin того же scope
снова показывает сохранённые. PIN event инвалидирует и обновляет снимок заметок.

- Mac/Linux Tauri и production/release-производительность здесь не проверены.
- Backend имитирует согласованный контракт; новая реальная серверная версия и
  миграция не публиковались и не проверялись на пользовательских данных.
- Одновременное редактирование outbox в нескольких вкладках одного аккаунта
  отдельным стресс-тестом не проверялось; запись снимков сериализована внутри
  одного экземпляра клиента. Серверная идемпотентность защищает один commandId.
- Фото/видео/файл проверены в существующем просмотрщике; отдельный нативный
  файловый менеджер и загрузка большого файла этой задачей не менялись.
