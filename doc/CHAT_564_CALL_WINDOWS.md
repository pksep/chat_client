# CHAT-564 — отдельное окно звонка

Ветка `chat-564`. По уточнению пользователя от 26.11 после проверок нужно слить актуальный main через PR и опубликовать Tauri. Production-веб и сервер отдельно не выкладываются.

## Реализация

- Дочерний DOM монтируется после завершения навигации WebView на собственный `about:blank#sep-chat-call`, а не во временный документ. Временная ошибка доступа к документу другого WebView допускает ожидание; отмена и закрытие прекращают подготовку.
- На Linux включено разрешение автоматических popup WebKitGTK для входящих вызовов. Нативный фильтр разрешает только собственную поверхность; сохраняются related view/configuration/environment и единственный RTC-контроллер.
- Отказ необязательного центрирования (например, на Wayland) не прерывает открытие. Неуспешный показ освобождает скрытую поверхность.
- Закрытие ожидает снятие слушателей; поздний ответ resize не вызывает необработанную ошибку уже уничтоженного окна.
- События `call.window.opening/unavailable/failed/shown/cancelled` записывают этап, длительность, версию/ОС оболочки и ограниченную причину отказа. Переход к встроенной модалке сохраняет звонок.
- В шапке звонка добавлен пин. Включение подтверждается состоянием ОС. На X11 читается EWMH-свойство самого окна: в нативной проверке WM выставлял ABOVE, но и Tao, и GDK возвращали старый false. Внешние процессы для работы кнопки не запускаются. Закрепляется только звонок; fullscreen временно снимает topmost и восстанавливает его при выходе. Новое окно начинает без пина.
- При достаточных размерах области участников Tauri показывает до девяти плиток. Область измеряется после шапки/управления, учтён резерв пагинации. При изменении размера страницы сохраняется видимость первого участника прежней страницы. Политики браузера/Android и качество медиа не менялись.

## Диагностика Натальи

26.11.2026 проверено 00:00–11:29 Asia/Yerevan (25.11 20:00–26.11 07:29 UTC), Loki client telemetry + chat-server + ограниченные LiveKit WARN. Актуальные источники находятся в `erp-i9-verify`, а не в старом `erp`.

Найден один звонок Натальи: `livekit-pt34qoqa`, подключение 10:59:21, выход по `user_leave` 11:17:46. Подтверждены Tauri/macOS и успешное подключение; оценка сети после входа — `excellent`. Версия приложения отсутствует в старой телеметрии, причины отказа popup она не записывает. Конкретная причина случая Натальи пока не доказана. Изменения устраняют найденные риски и добавляют недостающую диагностику; повторный звонок после установки исправления остаётся необходимым.

## Комментарии закреплений и поиск

- `PinCommentCard` останавливает dblclick: действие родительского сообщения не запускается; обычные действия карточки сохранены.
- Общий поиск показывает доступные комментарии под оригиналом; поиск внутри чата находит оригинал по тексту заметки и переходит к нему. На сервер отправляется opt-in `includePinComments=true`; это дополнение существующего поиска, не новый API заметок.
- Локально загруженные заметки находятся до сети. Очередь остаётся в общем хранилище CHAT-561; комментарии поиска не записываются поверх подтверждённого состояния. Изменение/удаление или ожидающая команда во время HTTP имеют приоритет над старым ответом. Смена SDK/пользователя отбрасывает ответ. SELF дополнительно фильтруются по владельцу.
- Для поиска заметок во всей истории требуется серверный [PR #253](https://github.com/pksep/chat_server/pull/253). Старый сервер продолжает обычный поиск; локальный поиск по уже загруженным заметкам доступен. Сервер и Android в основной рабочей копии не изменялись; серверное дополнение подготовлено отдельно от чужой ветки chat-563.
- Сервер: 5 интеграционных проверок PostgreSQL, ESLint и сборки общей библиотеки/сервера прошли. Использовалась отдельная база, пользовательские данные не менялись.

Нативная проверка macOS воспроизвела отклонение `about:blank%23sep-chat-call`: WebKit кодирует разделитель фрагмента, и прежний allowlist не принимал запрос. Теперь допускаются только оба точных варианта собственной поверхности и короткое одноразовое подготовленное `about:blank`. Установленный у Натальи бинарник и точная причина её старого случая неизвестны.

Виртуальные macOS-экраны CI имеют 1024×768: после системной рамки фактическая область сетки 1370×511, поэтому там корректны шесть плиток. Девять подтверждаются только при достаточной измеренной площади (включая Windows native и браузерные проверки). Это ограничение окружения фиксируется в report.json, а проверка не требует девять на недостаточной площади.

## Ограничения

Tao 0.37.2 не поддерживает topmost на Wayland; кнопка там отключена с пояснением. На X11 решение принимает оконный менеджер. На macOS обычное закрепление не обещает отображение поверх чужих полноэкранных Spaces. Работа самого отдельного окна проверяется независимо от поддержки topmost.

Нативные проверки используют вымышленных участников, отдельные профиль/идентификатор/схему, локальные серверы. Пользовательские сообщения и звонки не изменяются. Проверка синтетического интерфейса не заменяет проверку реального звонка у Натальи.
