# Микрофон и копирование ссылки из окна звонка — 27.11.2026

## Обращения

- macOS: основное окно чата свёрнуто, кнопка микрофона в отдельном окне иногда требует повторного нажатия, зелёная волна отсутствует.
- Первый диалоговый звонок: микрофон включён, но локальный индикатор голоса не появляется.
- Ссылка на звонок не копируется из отдельного окна.

## Исправления и основания

У отдельного окна Tauri не был включён `accept_first_mouse`: AppKit мог использовать первый клик только для активации окна. Параметр включён для окна звонка. Это устраняет соответствующий путь потери клика, но без проверки на физическом Mac нельзя утверждать, что он объясняет каждый случай из обращения.

Локальный аудиоанализатор восстанавливал только состояние `suspended`, пропускал WebKit `interrupted`, а незавершённый `resume()` блокировал повторную попытку. Теперь новый жест, возврат фокуса и видимости возобновляют анализатор, в том числе при зависшей предыдущей попытке. Граф анализа подключён к беззвучному выходу, чтобы WebKit его обрабатывал. Используется существующий RTC-track: повторный захват микрофона не запрашивается, его остановкой анализатор не управляет.

В главном окне для настольного диалогового звонка добавлен такой же локальный анализ реального микрофонного трека. Волна больше не зависит только от событий активного спикера с сервера. Пока анализатор не готов, сохранён прежний источник состояния LiveKit. При выключении микрофона кадры анализа и волна сбрасываются.

Копирование использовало `navigator.clipboard` и документ главного окна, хотя пользователь нажимал кнопку в дочернем. Теперь используются буфер и документ окна звонка. Для асинхронного создания приглашения запись начинается непосредственно в обработчике клика: обещание текста передаётся в `ClipboardItem`, что сохраняет необходимый WebKit пользовательский жест. Запасное текстовое поле создаётся внутри открытого native dialog, затем удаляется с восстановлением фокуса и выделения. Результат или ошибка видны в самом окне звонка; ошибка приглашения и ошибка буфера не показываются как успех.

## Проверки

- `bun test test/desktopMicrophoneMeter.test.ts`: 4 теста, 27 проверок. Первое включение, позднее появление и замена трека, `interrupted`, зависший `resume`, возврат фокуса, очистка ресурсов без остановки RTC-track.
- Playwright: главный и отдельный диалоговый звонок, настоящие Web Audio и синтетический звуковой поток; серверные `audioLevel` и `isSpeaking` намеренно равны нулю. Проверяются первый клик, меняющаяся зелёная волна, повторное выключение/включение и возврат фокуса.
- Playwright: обычная и компактная панели звонка, буфер именно дочернего документа, запасной путь внутри dialog, восстановление фокуса, ошибка и повтор, начало записи до ответа сервера. Отдельно проверена фактическая запись и чтение ссылки в системном буфере Chromium.
- В локальной Windows-сборке Playwright WebKit отсутствуют Web Audio и MediaStream: два звуковых сценария явно пропускаются. Прерывания WebKit дополнительно покрыты модульными тестами; для настоящего Web Audio предусмотрен прогон WebKit на macOS ARM и Intel.
- Итог локального прогона четырёх связанных E2E-файлов: 22 успешных сценария, 4 явных пропуска (два Web Audio в Windows WebKit и два сценария настоящего буфера, предназначенные только для desktop Chromium). `bun run lint` и финальная `bun run build:prod` завершились успешно.
- `cargo check --locked` успешно выполнен на Windows. Нативный первый клик AppKit и реальный захват микрофона на физическом Mac этой проверкой не подтверждаются.
- [Первый macOS-прогон](https://github.com/pksep/chat_client/actions/runs/45962890638): Intel — 5 сценариев без повторов; ARM — 4 сразу и 1 после повтора. В стенде найдено окно между показом кнопки и установкой обработчика тестового источника звука. Добавлено явное ожидание готовности стенда и состояние аудиопотока при сбое. Локально оба звуковых сценария повторены по три раза: 6 успешных проверок. Для повторного macOS-прогона включены три независимых повторения каждого сценария и отключены retries.

Изменения не требуют новых разрешений пользователя. Версии приложения, установщики, update-feed и production-веб в рамках этой работы не публикуются.
