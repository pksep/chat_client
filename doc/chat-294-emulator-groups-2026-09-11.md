# CHAT-294: группы, IndexedDB и Android-эмулятор

После передачи телефона пользователю Android-проверки выполнялись только на
`emulator-5556`. Сервер на этом этапе не менялся. На эмулятор установлена
актуальная debug APK ветки `chat-294` (`sep.pksep.app` 1.6.6).

## Что изменено

- Снимок истории `topicSnapshots` читается параллельно с независимыми
  служебными данными. Сохранённое окно сообщений публикуется сразу после
  проверки удалений, не ожидая восстановления вложений.
- Видимые строки списка заранее читают до 48 сообщений топика из IndexedDB.
  Работают не более двух фоновых чтений; HTTP-прогрев не выполняется.
- `pointerdown` повышает приоритет выбранного топика. Перед маршрутом клиент
  ждёт уже начатое чтение кеша не более 80 мс, поэтому первое содержательное
  состояние обычно содержит всё сохранённое окно, а не только `lastMessage`.
- Краткое сообщение из списка получает автора из уже загруженных участников
  группы или DM. Это не создаёт запрос справочника пользователей.
- DOM сообщений имеет ключ текущего топика. Узлы предыдущей группы не
  переиспользуются после смены маршрута.
- `CachedAvatar` передаёт готовый `data:`, `blob:`, `file:`, HTTP или локальный
  URL компоненту синхронно. Проверенные URL запоминаются в памяти, а CSS fade
  изображения отключён.

## Стенд

- Android 16 / API 36.1, AVD `chat294_api36`, два CPU, 2048 МБ RAM,
  экран 720×1280, программный рендеринг SwiftShader.
- Локальная HTTP-фикстура: 11 групп по 5000 сообщений и 4000 пользователей.
  Клиент получает страницу истории, а не весь набор из 55 тысяч сообщений.
- У `lastMessage` группы нет полного автора и реакций. Сетевая история и
  настоящий IndexedDB `topicSnapshots` содержат фото автора и реакцию 👍.
- В `topicSnapshots` проверено 72 сообщения. Ответ истории задержан на 2000 мс;
  отдельно проверено чтение IndexedDB с искусственной задержкой 1000 мс.
- Касания отправляются через CDP как touch-события. После клика каждый
  `requestAnimationFrame` проверяется на скелетон, старый топик, реакцию и
  источник аватара.

Продовая сессия на эмулятор не переносилась, нагрузка на продовый сервер не
создавалась.

## Сеть и известное ограничение

Переход выбранного топика выполняет не более одного точного GET
`/api/messages/topic/:id?limit=...`. Запрос `/pinned` учитывается отдельно и не
является повторной загрузкой истории. IndexedDB-прогрев списка не выполняет
HTTP.

На сохранённом AVD ранее наблюдались два фоновых GET других topic hints с
`limit=128`. Их инициировал отложенный нативный `ChatBackgroundSync`/WorkManager
после предыдущих тестовых сессий. Это отдельная очередь нативной синхронизации,
а не переход выбранного топика. Поэтому абсолютное отсутствие фоновых запросов
для старой очереди пока не заявляется.

## Повторная проверка на физическом телефоне 14 сентября 2026

По новому разрешению пользователя актуальная APK установлена поверх основного
`sep.pksep.app` на `23117RA68G` с Android 16. Данные приложения, авторизация и

`chat-server-prod.pksep.ru`; серверный код не менялся.
