# CHAT-294: возврат к списку и Android-клавиатура

## Причины и исправления

На Redmi Note 13 Pro (Android 16) с локальным backend
`http://192.168.1.101:5001` воспроизведены обе проблемы.

При возврате из топика список сначала появлялся на 58 CSS-пикселей ниже
своего положения, затем поднимался. Причина — `transition: all` у
`.chat-container`: анимировалась высота строки заголовка CSS Grid.
В `src/assets/chat-container.css` переход ограничен цветом фона.
Размеры сетки сразу соответствуют новому экрану.

В переписке из 80 сообщений клавиатура уменьшала высоту WebView с 832 до
506 CSS-пикселей, но нижний край ленты не следовал за ней. Нижняя граница
последнего сообщения оказывалась на 288,3 пикселя ниже верхней границы поля
ввода. `useScrollAnchor` наблюдал только за содержимым ленты, высота которого
в длинной переписке не менялась.

В `src/components/Messages/composables/useScrollAnchor.ts` существующий
`ResizeObserver` теперь наблюдает также за областью просмотра. В режиме
чтения последних сообщений нижний край удерживается при изменении её
размера. При чтении истории принудительной прокрутки вниз нет.
Обработчик прокрутки также проверяет изменение размера: под нагрузкой
`scroll` может прийти раньше `ResizeObserver`, и такое событие больше
не переключает ленту в режим чтения истории.

Дополнительных обработчиков на `window`, таймеров опроса или сетевых
запросов для клавиатуры не добавлено. При размонтировании наблюдение
отключается вместе с существующим observer.

## Границы измерений

Нулевая прибавка HTTP в браузерной серии переходов проверяется внутри
интервала свежести кеша. В реальном длительном прогоне телефона продолжают
работать обновления истории/закреплений и фоновая телеметрия. Текущий
интервал свежести истории при переходах — 15 секунд. Отсутствие запросов
истории при открытии клавиатуры проверяется отдельно от этих операций.

Эта итерация исправляет поведение viewport; новые цифры ускорения холодного
запуска по ней не заявляются.
