# CHAT-294: физический Android и локальный сервер

Работа продолжается в `chat-294`. Устройство пользователя: Redmi Note 13 Pro
(`23117RA68G`), Android 16. Основное приложение `sep.pksep.app` от 9 сентября
сохранено вместе с авторизацией, кешем и перепиской. Для проверок установлен
отдельный пакет `sep.pksep.app.performance`, отображаемое имя — `CHAT-294 Test`.

## Исправления стартовой загрузки

`main.ts` повторно подключал UI-kit, Inter и глобальные стили, которые уже
входят в `assets/chat-container.css`. В собранной странице загружались три
CSS-файла: 2030 + 689125 + 951460 байт. Удалены повторные импорты из `main.ts`.
Остался тот же общий CSS размером 951460 байт, с тем же хешем содержимого.
Стартовая загрузка CSS уменьшилась на **691155 байт, или 42,1%**.
Библиотечный вход `src/index.ts` сохраняет общий файл стилей.

Синхронный `theme-init.js` в `<head>` требовал отдельного обращения WebView
к ресурсу APK до продолжения разбора HTML. В исходных замерах на телефоне
эта загрузка занимала 130–414 мс. Build-плагин `inline-startup-theme.ts`
вставляет содержимое существующего файла непосредственно в HTML и добавляет
точный SHA-256 в `script-src`. `unsafe-inline` для скриптов не добавлен.
CRLF нормализуется до вычисления хеша; сборка завершается ошибкой при отсутствии
CSP-директивы или закрывающем HTML-теге внутри скрипта. Dev-режим сохраняет
исходное подключение файла.

Это устраняет три загрузки локальных ресурсов при старте: два CSS и скрипт
темы. Речь о ресурсах приложения в WebView, а не о сокращении трёх запросов API.
Размер всей APK почти не изменился; сокращение стартовой загрузки не выдаётся
за сокращение установочного пакета.

## Стенд и сохранность данных

Нагрузочный runner принимает `ANDROID_PERFORMANCE_PACKAGE`. На физическом
телефоне разрешён только точный пакет `sep.pksep.app.performance`; дополнительно
проверяются DEBUGGABLE и наличие тестового приёмника. Основное приложение
разрешено runner-у только на выделенном эмуляторе. Сборка отдельного пакета
задаётся init-скриптом Gradle, без изменения обычного application ID.

На Xiaomi broadcast после `force-stop` не запускал тестовый приёмник.
Поэтому холодное уведомление на телефоне проверяется так: уведомление
создаётся штатным `ChatNotificationHelper`, приложение уходит в фон,
`am kill` завершает процесс, отсутствие PID проверяется, затем автотест
нажимает сохранённый системный PendingIntent. Это проверяет запуск после
выгрузки процесса; доставка RuStore после пользовательского force-stop
этим сценарием не проверяется.

Уведомления находятся штатным UIAutomator, без установки Playwright-драйвера
на телефон. Снимки снимаются через ADB: захват WebView в Playwright/CDP
на этом устройстве иногда зависал. Неудачные прогоны настройки стенда
сохранены отдельно и не используются как итоговое сравнение.

Есть два независимых набора данных:

- Локальный HTTP/WebSocket-стенд на 5188: 4000 пользователей, 50 историй по
  5000 сообщений. В стартовый кеш помещаются первые три истории. Проверяются
  задержки сети, HTTP 503, гонки уведомлений, 20 обычных переходов, 20 системных
  уведомлений и поток из 300 событий сообщений.
- Настоящий локальный backend на `http://192.168.1.101:5001`: 50 групп,
  созданных только для двух тестовых пользователей, и «Избранное». Проверяется
  запуск собранной APK с реальной БД и корпоративной конфигурацией.
  Группы и сессия остаются доступны в тестовой копии приложения.

Старый процесс сервера на 5001 завершился во время подготовки; локальный
сервер запущен снова из существующего `dist`, с `NODE_ENV=development`.
Причина завершения старого процесса не установлена. Vite на 5173 сохранён.

от смены маршрута до правильного видимого содержимого. В обеих сериях —

На реальном backend в каждой серии сначала выполнялся запуск без кеша,
затем три запуска с кешем. Для сравнения используются последние три:

Во всех случаях отображается 51 строка. Первые запуски не используются
для прямого сравнения: в первой серии ещё создавалось «Избранное».

## Интерпретация замеров

Основная метрика запуска — `chat-startup:shell-removed`, время от начала
навигации WebView. Она не включает создание Android-процесса и WebView.
`firstReadyAt` — первый кадр, замеченный подключённым наблюдателем; на быстром
телефоне наблюдатель иногда подключается уже после появления списка.
`processStartToObservedReadyMs` включает ADB/CDP и не является точным временем
от нажатия иконки до готовности приложения.

Для переходов используется время от изменения маршрута до правильного
видимого содержимого. Скелетон при задержанной загрузке отсутствующего в кеше
чата ожидаем; ноль требуется для повторных переходов к доступному содержимому.
Замеры установленной старой версии на production-ссылке не сравниваются
напрямую с тестовыми данными локального backend.

## Воспроизведение

```powershell
# Из chat_client. Отдельный пакет для личного телефона.
bun run build:android
node node_modules/@capacitor/cli/bin/capacitor copy android
./android/gradlew.bat -p android -I ../scripts/android-performance.init.gradle :app:assembleDebug -PrustorePushProjectId=chat-294-local-performance

$env:ANDROID_PERFORMANCE_SERIAL='192.168.1.100:35579'
$env:ANDROID_PERFORMANCE_PACKAGE='sep.pksep.app.performance'
$env:ANDROID_PERFORMANCE_PHASE='phone-reproduction'
$env:ANDROID_PERFORMANCE_CACHE='shadow'
$env:ANDROID_PERFORMANCE_TOPIC_COUNT='50'
$env:ANDROID_PERFORMANCE_FIRST_LIST='1'
$env:ANDROID_PERFORMANCE_TOPICS='1'
$env:ANDROID_PERFORMANCE_STRESS='1'
$env:ANDROID_PERFORMANCE_ITERATIONS='20'
node --experimental-strip-types scripts/verify-android-performance.ts
```

Этот runner очищает **только тестовый пакет на телефоне**. Для обычного
измерения без изменения данных служит `scripts/measure-android-startup.ts`:
он только перезапускает процесс, сохраняет обезличенные тайминги и не очищает
авторизацию/кеш. Не запускать сборку и браузерные тесты одновременно с замером.
