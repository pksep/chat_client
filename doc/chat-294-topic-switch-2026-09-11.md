# CHAT-294: переключение топиков на физическом Android

Ветка `chat-294`. Redmi Note 13 Pro (Android 16), отдельное приложение
`sep.pksep.app.performance`, локальный backend `http://192.168.1.101:5001`.
Основное приложение `sep.pksep.app` и его данные не изменялись.

## Причины задержки и изменения

1. При каждом входе из мобильного списка заново создавался ContentEditor
   со скрытой панелью эмодзи. В коротком топике было около 4100 DOM-элементов.
   Профиль показал создание/удаление DOM, фильтрацию эмодзи, layout и GC.
   Патч UI-kit теперь создаёт picker после первого нажатия на смайлик.
   Повторное открытие панели внутри одного редактора использует тот же экземпляр.
2. Android добавлял анимацию сдвига длительностью 220 мс после создания интерфейса.
   Нативный переход теперь отображает готовый топик сразу.
3. Первый кадр монтировал 48 сообщений независимо от высоты телефона.
   Теперь окно зависит от высоты экрана и непрочитанных, в пределах 24–48.
   В данном телефоне это 28 сообщений. Остальное окно расширяется существующим
   отложенным механизмом, с сохранением нижнего края и отменой при уходе из топика.
4. На мобильном уже загружались 72 сообщения одним запросом, но через 80 мс
   запускался ещё один проход расширения. HTTP обычно объединялся кешем,
   однако UI сразу монтировал 72 сообщения и создавал вторую длинную задачу.
   Этот проход оставлен для desktop, где он по-прежнему нужен.
5. WebView повторно запрашивал `/images/favicon.ico` при `replaceState`.
   Для нативного Android favicon заменён пустым data URL: иконку приложения
   задают ресурсы Android. Веб-версия сохраняет обычный favicon.
6. Проверка клавиатуры обнаружила редкое отклонение на 5 px. Отдельно воспроизведён
   рост `scrollHeight` без ResizeObserver при трансформации содержимого.
   Scroll-событие ошибочно переводило ленту в режим чтения истории.
   Теперь при обработке scroll учитывается изменение прокручиваемой области;
   режим чтения истории сохраняется, если пользователь действительно ушёл вверх.

MessageList по-прежнему уничтожается при возврате к списку. Поэтому жизненный
цикл черновиков, вложений, редактора и обработчиков не заменён бессрочным кешем
компонентов. Сеть сохраняет TTL и обновление устаревшей истории.

## Замеры на телефоне

`artifacts/measure-chat294-topic-switch.cjs` чередует две локальные группы:
Phone 49 с 80 текстовыми сообщениями и Phone 48 с одним системным сообщением.
В каждой серии — 20 открытий с возвратом к списку. Ни сборки, ни браузерные
нагрузочные тесты одновременно с измерением телефона не запускались.

Итоговая серия `final`, повторные открытия без первых двух посещений:

| Метрика | До | После |
|---|---:|---:|
| Длинный топик: медиана первого кадра | 352,8 мс | 186,8 мс |
| Длинный топик: p95 | 395,8 мс | 201,8 мс |
| Короткий топик: медиана первого кадра | 202,3 мс | 90,9 мс |
| Короткий топик: p95 | 217,9 мс | 99,3 мс |
| DOM в длинном топике после открытия | 5123 | 1295 |
| DOM в коротком топике после открытия | 4099 | 896 |

В 18 повторных переходах `final`: 0 завершённых загрузок истории/закреплений, 0 запросов favicon,
0 кадров скелетона и 0 наблюдаемых кадров чужого топика. Остались два штатных
пакета телеметрии. Первые посещения после запуска тестовой APK: 357 и 149 мс;
это другой сценарий, его нельзя смешивать с повторным переходом из памяти.

Длительность измеряется от обработчика выбора до кадра с DOM сообщений.
Это не измерение аппаратного времени вывода пикселей на дисплей. В новых сериях
проверяются ID сообщений нужной группы и завершение анимации; исходная серия
`before` проверяла наличие сообщений, без проверки ID. В серии только с ленивыми
эмодзи окончание анимации занимало в медиане 558/339 мс; после её удаления
готовность кадра и отсутствие анимации совпадают.

Дополнительно выполнены 10 переходов через `Input.dispatchTouchEvent` WebView,
с проверкой `event.isTrusted`. В повторных открытиях медиана — 180,2/91,4 мс,
p95 — 222,0/101,3 мс (длинный/короткий). Кадров скелетона и чужих сообщений нет.
Первый кадр измеряется от события выбора, без времени удержания пальца.

## Автоматические проверки

В браузерном стенде проверены два режима: прямое переключение MessageList и
полный цикл Chat со списком, созданием и уничтожением редактора.
По 300 переходов на каждом проекте в каждом режиме; история по 5000 сообщений.
В полном цикле p95 составил 44,3/52,3 мс (desktop/mobile), 0 дополнительных HTTP,
0 кадров скелетона, 0 кадров чужого топика, 0 прироста DOM и обработчиков после GC.
Рост heap — 2,4/3,5 МиБ, в пределах прогрева. Эти числа относятся к браузеру
на компьютере, а не к физическому телефону.

В первом общем прогоне: 53 из 54 сценариев прошли; один тест клавиатуры обнаружил
отклонение 5 px. После исправления и добавления проверки scrollHeight прошли
все 16 сценариев viewport/редактора, включая эмодзи внутри вложения и черновики.
До исправления исходный тест также прошёл 10 повторов: это не отменяло найденную
гонку, поэтому она воспроизведена отдельным детерминированным сценарием.

95 unit-тестов клиента прошли. Три устаревшие проверки темы исправлены:
добавлен отсутствующий `matchMedia` в DOM-мок и убрана привязка к старой версии
URL скрипта. Поведение приложения ради этих тестов не менялось.

Последний прогон на итоговом коде: ещё 1200 переходов (по 300 на каждый режим
и браузерный проект) и восемь сценариев уведомлений, все 12 тестов прошли.
Для полного цикла p95 — 123,1/116,1 мс, для прямого переключения — 154,3/93,5 мс.
Во всех четырёх нагрузках: 0 дополнительных HTTP, 0 скелетонов и отсутствие
роста DOM/обработчиков. Разброс между прогонами на компьютере существенен;
основной результат Android подтверждён отдельными замерами на устройстве.

Итоговая APK собрана с проверкой типов; 16 Android unit-тестов прошли.
Установлен пакет `sep.pksep.app.performance`, 74 769 924 байт,
SHA256 `0c6cebee4e92161d68f6679207bfdaffa189c1724e624505ab59a1824e6e34b7`.
Хеш установленного `base.apk` совпадает. Время обновления основного приложения
осталось `2026-09-09 17:53:12`.

На итоговой APK дополнительно прошли 20 открытий/закрытий клавиатуры и 20
возвратов при разных позициях списка. Максимальное расстояние от нижнего края
при открытой клавиатуре — 0,091 CSS px, последнее сообщение видно над инпутом.
Смещение списка и его прокрутки — 0 px, смещение места чтения истории — 0 px.
Возврат с открытой клавиатурой тоже прошёл (73 наблюдаемых кадра).
В циклах клавиатуры — 0 запросов данных. В длительных возвратах остаются
штатные чтения впервые открываемых топиков и обновления после TTL.
Ошибок страницы нет. ADB forward удалён; процессы 5001/5173 сохранены.
