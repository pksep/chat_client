# Окна пересылки и создания

При малой высоте WebKit центрировал окно пересылки по всему viewport,
не учитывая хедер Tauri. Появлялись два скролла, часть списка обрезалась.
Та же схема размеров использовалась в создании чата и бота.

Для этих окон ограничены высота и положение по доступной области приложения.
Заголовок остаётся видимым, прокручивается список получателей или форма бота.
В тёмной теме размеры учитывают рамку. В узком Tauri мобильные окна также
занимают область под хедером; нижние кнопки остаются доступными.

Проверки: Chromium/WebKit, высоты 400/640/800, обе темы, поиск/пустой список,
последний получатель, поля/кнопка создания и закрытие. На Windows прошёл
21 уникальный сценарий, включая мобильную браузерную регрессию и 6 проверок
узкого Tauri. Скриншоты просмотрены. Реальные сообщения/боты не создавались.

Desktop Builds дополнительно запускает эти проверки на macOS обеих архитектур
до публикации feed. Это WebKit-проверка в macOS CI; ручная проверка UI на
компьютере пользователя ещё не выполнялась.

## Настройки звонка, 24 ноября

Боковая панель настроек звонка использовала `top: 0` и попадала под хедер
Tauri. Теперь её оболочка занимает область под хедером, а сама панель
привязана к оболочке. Это сохраняет положение и во время transform-анимации
открытия. Высоту прокручиваемого содержимого задаёт flex-контейнер; заголовок
и закрытие остаются видимыми при малой высоте окна.

Chromium/WebKit: проверены обе темы, высоты 400/640/800, открытие по кадрам,
прокрутка до последнего участника, закрытие, fullscreen и узкий Tauri.
Браузер и Tauri с системной рамкой сохраняют панель на весь viewport.
Полный набор оболочки: 37 проверок прошли, одна прежняя проверка захвата
пропущена в WebKit из-за отсутствия `canvas.captureStream`. Снимки обеих тем
просмотрены. Нативный установщик ради этой проверки не запускался.
