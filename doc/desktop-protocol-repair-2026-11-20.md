# Открытие установленного приложения из браузера

20 ноября 2026 пользователь сообщил, что «Открыть в приложении» не запускает
СЭП Чат. Установленный Windows-клиент — 1.53.6, веб-сборка на домене — 111.

Проверка Windows обнаружила отсутствие обработчика `sepchat` в HKCU и HKLM.
Запись автозапуска `SEP Chat` указывала на удалённый QA-клиент из
`.codex/desktop-updater-native/installed`. Тестовый Windows NSIS-установщик
наследовал боевую схему `sepchat` из базовой конфигурации, а его release-процесс
перезаписывал общий автозапуск. Удаление QA-пакета убирало обработчик протокола.

Для текущей установки восстановлены только пользовательские записи протокола
и автозапуска с проверенным существующим `sep-chat.exe`. Системный запуск
`sepchat://open` открыл установленный клиент, процесс отвечает. Пользователь
также подтвердил запуск кнопкой из своего браузера. Переустановка или новая
версия Tauri для восстановления не потребовалась.

Защита от повторения:

- Windows updater QA использует собственный протокол `sepchat-updater-qa`.
- Регистрация боевого автозапуска выполняется только для `ru.pksep.chat`;
  другой identifier не записывает `SEP Chat` в Run.
- Нативный QA сравнивает регистрацию рабочего протокола и автозапуска до
  установки, обновления и удаления тестового приложения и после них.
- Rust-тест проверяет, что вызов регистрации для QA не изменяет боевой Run.

Новая desktop-версия в рамках этого исправления не публикуется. Параллельные
изменения разрешений устройств не входят в этот коммит.
