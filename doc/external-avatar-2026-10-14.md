# Аватар клиента внешнего канала

## Поведение и причина

ВК передаёт аватар посетителя, Manager доставляет адрес в профиль Чата.
Однако `CachedAvatar` загружал любую внешнюю картинку через `fetch` с credentials,
чтобы положить её в кеш. CDN может отдавать картинку для `img`, но запрещать
чтение ответа скриптом другого сайта. При таком отказе компонент оставлял инициалы.

## Изменение и предотвращение

Для абсолютного HTTPS-аватара без логина и пароля используется обычное изображение.
Подписанный адрес сохраняется целиком. Картинка проверяется перед показом, при
реальной недоступности остаются инициалы. Предзагрузка не передаёт referrer.
Относительные пути файлов Чата и приватные вложения не меняют правила доступа.
Нельзя требовать разрешение CDN на чтение данных скриптом для простого отображения.

## Проверка

`bun test tests/direct-avatar-url.spec.ts` проверяет подписанные ссылки,
локальные пути и небезопасные адреса. `bun run test:e2e --config
playwright.avatar.config.ts` проверяет настоящий `CachedAvatar` на компьютере
и телефоне: изображение без CORS-заголовков показывается, `fetch` того же адреса
отклоняется, при 404 появляются инициалы, после смены адреса аватар восстанавливается.
Площадки и реальные клиенты не вызываются: ответы CDN подменяются в браузере.

Полный локальный набор `bun test ./test ./tests --timeout 30000`:
234 успешных, 8 упавших, 0 пропущенных. Все 8 отказов есть и на исходном
`8ddf97dc`: 5 проверок AI-потока без настройки доступа, 2 устаревших ожидания
цвета темы и отсутствие `requestAnimationFrame` в проверке уведомлений.
Это не успешный полный прогон. Проверка типов, production-сборка и проверка
изменённых файлов ESLint проходят. Серверный код и миграции не меняются.
