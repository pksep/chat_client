# Скачивание файлов: проценты и Safari на iPhone

В Tauri уже приходили события с процентом скачивания, но карточка файла
показывала только кольцо. Теперь в сообщении и списке вложений рядом
с размером видны проценты. Пока сервер не сообщил размер, отображается
«Скачиваем…». Прогресс сглаживается, крестик и подтверждение отмены сохранены.
Общий компонент также используется для существующего Android native progress.
NaN/Infinity из события не заменяют известное значение прогресса.

Обработчик веб-скачивания перехватывал ссылки media/object с downloadName
и открывал их в скрытом iframe на всех платформах. Для iOS web такой путь
заменён обычной ссылкой с target=_blank и rel=noopener: Safari получает
attachment в рамках исходного клика, вкладка чата и звонок остаются открыты.
Программное скачивание использует тот же путь, включая локальные blob-ссылки.
Для файла с другого домена Safari может открыть отдельную вкладку.

Проверено: 38 Playwright-сценариев Chromium desktop/mobile, WebKit desktop
и iPhone; два платформенных сценария beforeunload пропущены вне desktop
Chromium. Ещё четыре проверки больших файлов подтверждают старт скачивания
до получения тела, в том числе только по заголовкам. Проверены содержимое
полученного файла, проценты/неизвестный размер, список вложений, отмена,
повторная загрузка, поздние события, сохранение чата/звонка и просмотрщика.
Снимок WebKit с процентами и крестиком просмотрен. Полные lint/typecheck
и production Vite/PWA build проходят.

Это не испытание установленного Mac-приложения или физического iPhone.
Игнорирование скачивания в Safari на устройстве остаётся проверить после
выкладки; подтверждена замена подозрительного iframe-пути и получение файла
в WebKit. Веб-скачивание по-прежнему передаётся браузеру без сборки больших
файлов в JS-памяти; проценты внутри карточки добавлены для нативного скачивания.
Серверные контракты, публикация веба, установщики и update-feed не менялись.
