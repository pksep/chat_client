# Сохранение разрешений Tauri при перезапуске и обновлении

Ответы по микрофону, камере, геолокации, уведомлениям и чтению буфера раньше
хранились только в localStorage WebView. Потеря этого профиля возвращала запросы
доступа даже при неизменном bundle identifier. Это подтверждённая уязвимость
механизма хранения, а не доказанная причина на компьютерах Давида и Олега.

Теперь источником ответов служит `desktop-permissions.json` в `app_config_dir`,
привязанном к постоянному `ru.pksep.chat`. При первом запуске туда переносятся
старые ответы. Дальше native-файл имеет приоритет перед localStorage, включая
пустой файл после явного сброса. Запись выполняется в фоновом потоке через
временный файл, `sync_all` и замену файла. Перед установкой обновления ожидаются
незавершённые записи. Повторное использование разрешения не пишет файл заново.

В файле нет координат, содержимого буфера, токенов или медиаданных. При ошибке
записи текущий звонок/вставка продолжаются; в профиле отображается предупреждение.
Системные ограничения ОС по-прежнему действуют. Запись экрана проверяет разрешение
ОС по требованию, а экран/окно пользователь выбирает для каждой демонстрации.
Файловые операции используют уже выбранный файл или штатный диалог выбора;
отдельное разрешение на все файлы не требуется. Автозапуск сохраняет существующую
регистрацию и не запрашивается при каждом звонке.

Для уведомлений Windows читается `ToastNotifier.Setting`: штатный desktop-плагин
Tauri всегда сообщал Granted. Ошибка чтения отличается от запрета и показывается
в профиле. Режим «Не беспокоить» и отключённые баннеры пользователь меняет в Windows.
Установщик повторно выставляет AppUserModelId существующим собственным ярлыкам,
в том числе после уже завершённой миграции имени; удалённые пользователем ярлыки
не создаются повторно этим исправлением.

Проверки:

- Unit: сохранение всех ответов, перенос, повреждённые данные, потеря localStorage,
  отказ записи, сброс и запрет Windows, который не видит notification-плагин.
- Rust: повторное открытие файла, однократный перенос, сброс и ошибка атомарной записи.
- Chromium/WebKit: разрешения камеры/микрофона, геолокация, интерфейс настроек,
  запрос экрана. WebKit без canvas.captureStream пропускает один сценарий.
- `bun scripts/test-desktop-permissions-native.ts`: три отдельных процесса Tauri
  с изолированным профилем и тестовыми медиоустройствами. В первом запуске два
  согласия (микрофон, затем камера), во втором после удаления WebView-ответов —
  ноль запросов, после явного сброса в третьем — новый запрос с проверкой отказа.
- `bun scripts/test-windows-shortcuts.ts`: 16 сценариев, включая реальное чтение
  System.AppUserModel.ID восстановленных ярлыков с правильным target.

Результат: 23 проверки разрешений (19 Bun и 4 Rust), 19 проверок updater/release,
47 UI-проверок успешно и 1 пропущена. ESLint, production build и `git diff --check`
прошли. Нативный отчёт:
`test-results-native/permissions-96b999ed-064c-4ae9-a41a-af45c97a4f09/report.json`.

По последующему поручению пользователя изменения опубликованы в **Tauri 1.54.2**.
Результаты публикации: [desktop-release-1.54.2.md](../desktop-release-1.54.2.md).
Нативное восстановление разрешений проверено на Windows; CI дополнительно проверил
обновление и диалоги macOS обеих архитектур. Это не заменяет отдельную проверку
физических микрофона/камеры и системных разрешений на компьютере Mac пользователя.
