## Камера и старые фото

WebKit может вернуть непустой `input.files`, когда чтение файла ещё завершается
ошибкой `NotReadableError` либо размер временно равен нулю. Input остаётся в DOM,
пока клиент до 10 секунд повторяет создание независимой копии файла. Проверки
размера и допустимости вложений сохранены. Обработчик отправки находится за
пределами повторов; загрузка не дублируется.

Для завершённых изображений добавлено ограниченное восстановление превью:
повреждённый кеш → прямой адрес миниатюры → оригинал. Приватные вложения обращений
с Bearer-авторизацией продолжают использовать прежний защищённый путь.

В Loki для Федоровой 2 ноября в 11:20–12:05 найдены успешные загрузки скриншотов
замечаний, но не найдена сама попытка отправки снимка камеры. Это согласуется со
сбоем до загрузки, однако точную причину конкретной попытки не доказывает.
Проверка 29 октября также не нашла загрузки проблемного снимка. Новые сценарии
воспроизводят ошибки чтения на стороне клиента. Исправление превью поможет, если
оригинал доступен; оно не восстанавливает отсутствующие или повреждённые серверные
объекты. Такие объекты по присланному скриншоту не установлены.

## Запуск и PDF

Мобильная панель PDF теперь имеет высоту 48 px; кнопки 40 px расположены по центру,
с отступом 4 px внутри панели. Системная нижняя безопасная область остаётся
отдельно. Проверены один PDF и альбом в светлой и тёмной темах.

Фон страницы задаётся сразу после charset: `#f8f9fd` для светлой темы и `#212531`
для тёмной темы ОС. Сохранённая тема уточняется штатным ранним скриптом. Начальный
фон больше не анимируется из белого. Фон манифеста также соответствует приложению.

У SVG убран `shape-rendering="crispEdges"`, отключавший сглаживание двух контуров.
Исходные градиенты и форма логотипа сохранены. У PNG-заставок убрана палитра из
128 цветов с dithering; пересозданы 76 изображений, около 3,2 МБ суммарно. Ссылки
заставок получили версию `20261102`. Первый кадр HTML и PNG проверены отдельно.

## Ранее подготовленные исправления

Сохранены исправления предыдущих замечаний: камера, аватар, кнопки звонилки,
обои чата и ИИ, стикеры «Коты», иконки, PDF и обложка нового видео после отправки.
Подробности находятся в отчётах за 28, 29 и 30 октября.

Сохранено исправление истории: кешированные сообщения видны во время обновления;
два новых сообщения из сокета не считаются подтверждением загруженного контекста.
Клиент читает сообщения перед первым непрочитанным из локального хранилища и
обновляет историю по HTTP, повторяя временно неудачное чтение в фоне.

По уведомлениям Давида Перова подготовлен клиентский путь показа из сокета для
Chrome без изменений сервера. Причины, доказательства и ограничения описаны в
`investigations/2026-11-02-perov-web-notifications.md`.

## Проверки

- 28 сценариев камеры, обложки видео и ограничений вложений прошли в Chromium
  mobile и WebKit iPhone PWA. Проверены точные байты, задержанная доступность,
  `NotReadableError`, временный размер 0 и отсутствие повторной отправки.
- Четыре сценария восстановления фото прошли в обоих движках. В Chromium
  повреждённый Blob записывается в настоящий IndexedDB. Windows WebKit не
  позволяет сохранить тестовый Blob (`UnknownError`), поэтому в нём повреждение
  создаётся в настоящем кеше Blob в памяти через ответ загрузки; последующее
  восстановление выполняется кодом приложения. Проверяются загрузка оригинала,
  декодирование изображения и число запросов.
- 17 применимых проверок PDF/слайдера прошли; один сценарий только для WebKit
  штатно пропущен в Chromium. После уточнения снимков повторно прошли восемь
  вариантов нижней панели и четыре варианта заставки. Готовый PDF и обе темы
  заставки просмотрены на снимках.
- В повторной проверке старых замечаний прошли 19 из 20 сценариев. Сценарий эмодзи
  WebKit исчерпал общий лимит времени на холодной загрузке и действиях редактора.
  Лимит двух сценариев эмодзи приведён к 90 секундам; оба прошли отдельным прогоном
  с трассировкой без изменения продукта ради теста. Финальный повтор с артефактами
  вне дерева Vite прошёл за 36 секунд. Один дополнительный запуск через Bun с
  управляемым Vite завис при завершении и был остановлен; финальная проверка
  выполнена напрямую через Node CLI Playwright с отдельно запущенным Vite.
- Клиентский путь уведомлений: E2E Chromium desktop и девять модульных тестов
  service worker прошли, включая mute, упоминания и отсутствие дублей.
- `bun run build` прошёл: проверка типов, production-сборка и PWA. Остались
  обычные предупреждения Vite о размерах чанков и совмещённых статических и
  динамических импортах.
- `node --experimental-strip-types scripts/verify-iphone-startup.ts` прошёл
  на финальной сборке во всех четырёх сочетаниях Chromium/WebKit и темы.
  JS, CSS и внешние SVG задержаны; первый кадр содержит фон приложения и логотип.
- ESLint всего `src`, изменённых тестов и service worker (окружение serviceworker),
  Prettier изменённых файлов и `git diff --check` прошли. Большой существующий
  CSS не переформатировался целиком: в нём добавлены только правила панели.

Системная камера и начальный снимок ОС на физическом iPhone не проверялись.
WebKit на Windows воспроизводит возврат из камеры и временные ошибки файла;
последующая подготовка, загрузка и формирование сообщения используют настоящий
код приложения. Production не менялся.
