# Мультимедиа AppImage

В 1.52.2 AppImage содержала ядро GStreamer 1.20.3 без собственного набора
плагинов. В Ubuntu 26.04 с системными плагинами 1.28.2 это вызывает ошибку
`undefined symbol: _gst_value_unique_list_type` при сканировании плагинов.
Исходная AppImage не проходит проверку комплектации мультимедиа.

Включена `bundleMediaFramework`: ядро, плагины и scanner собираются из одной
Ubuntu 22.04. Hook AppRun изолирует пути плагинов от системных. Устанавливаются
base/good/bad/libav, nice и PulseAudio; нужны звук, Opus, VP8 и WebRTC.

`check-linux-media.sh` извлекает настоящий пакет и использует его hook.
Проверка загружает требуемые фабрики и проверяет, что плагины взяты из AppImage.
Публикация desktop-feed блокируется до успешной проверки на Ubuntu 22.04,
24.04 и 26.04. Локальная проверка:

```sh
bash .github/scripts/check-linux-media.sh /path/to/SEP-Chat.AppImage
```

Для компиляции диагностического probe нужны C-компилятор, pkg-config и
libgstreamer1.0-dev. Это зависимости проверки, не обычной установки AppImage.

Полное падение WebKitWebProcess под Hyprland/Wayland локально не воспроизведено.
Старт исходного приложения под Xvfb не завершился SIGABRT за 25 секунд.
Исправление устраняет подтверждённое смешивание ABI; поведение серого экрана
на исходном окружении требует повторной проверки пользователем.

Видимое имя — «СЭП Чат». Linux productName сохраняет `SEP Chat`, чтобы Debian/
RPM имели допустимый прежний идентификатор `sep-chat`. Имя в `.desktop`
переведено отдельным шаблоном; бинарник и каталог данных остаются прежними.
Имена файлов GitHub Releases также сохраняют ASCII для стабильных ссылок.
