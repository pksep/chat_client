Проверены Chat Client #481 (`7c2e6824`) и Chat Server #242 (`5a3af219`).
Серверное ревью не обнаружило блокирующих ошибок; в изолированной копии прошли
сборки общей библиотеки и Nest, lint изменённых файлов и 173 теста. PostgreSQL

PR содержит миграцию AI-папок, MCP, диктовку и расширение Manager/WhatsApp.

В клиентском PR исправлены отсутствующий desktop cfg у команды чтения вывода
агента и разбор предупреждений stdout в recovery-тесте. Независимое ревью
проверило ещё 99 тестов voice/approval/AI/WhatsApp.

## Исправления по замечаниям

- Обычный клик по закреплению не закрывает список. Явный переход «Показать в
  чате» остаётся в общем контекстном меню. Выбор сообщений и вложения сохраняют
  свои действия. Аналогичное изменение внесено в нативный Android.
- Редактор скрывается вместе с открытием списка, сохраняя экземпляр, черновик
  и геометрию переписки. Приостановленный редактор не принимает Tauri file drop.
- Убран пустой flex-элемент выбора, создававший отступ у пузыря; полоса
  прокрутки больше не резервирует симметричный лишний отступ.
- Ошибка организации показывает, что сервер не найден либо временно недоступен.
  HTTP 200 с HTML вместо конфигурации также отклоняется. Сохранённая организация
  и её fallback не удаляются при временной недоступности.
- Веб-версия в `public/web-update.json` повышена до 119. Production-веб не
  развёртывается: последнее поручение относится к версии и отправке main.

## Windows: вход и тема

Версия, на которой Давид потерял состояние, неизвестна. Сам факт сброса после
обновления не доказывает его причину. Проверены идентификатор, настройки профиля
и NSIS hooks: `ru.pksep.chat` сохраняется, переименование не удаляет данные.
Путь WebView2 теперь задаётся явно через стабильный app local data directory;
ошибка определения пути не переключает приложение на случайный профиль.

Добавлена защищённая копия выбранной организации, постоянного входа и темы.
Windows DPAPI шифрует её для текущего пользователя; секреты не записываются
открытым текстом. Срок действия refresh cookie сохраняется как абсолютный,
HttpOnly/domain/path/secure не меняются. Удаление cookie удаляет её из копии.
Запись синхронизируется с диском, операции выполняются вне UI-потока.

Восстановление выполняется до создания Vue-приложения. Существующий профиль
приоритетнее копии; авторизация восстанавливается только при пустом профиле.
Явный выход и режим без запоминания обновляют копию без авторизации. Перед
установкой обновления ожидается запись копии и завершение storage-транзакций.

Это защита последующих обновлений: уже исчезнувшие данные, для которых копия
ещё не создавалась, восстановить из неё невозможно. Исходная причина конкретного
сброса у Давида остаётся неподтверждённой без диагностики его старой установки.

## Проверки

Успешны production-сборка Vue, проверка типов и отдельный ESLint (0 ошибок).
Новые unit-проверки охватывают неверную конфигурацию, ошибки сервера,
восстановление пустого профиля и сохранение выхода. Rust-проверки подтверждают
DPAPI roundtrip, отсутствие открытого секрета в файле, отказ при повреждении
шифротекста, замену копии после выхода и нативный auth HTTP transport.

Полный клиентский unit-прогон выявил три устаревшие фикстуры: зависимости
Manager, navigator для theme bootstrap и проверку внутреннего количества
waitUntil в push. Фикстуры исправлены, соответствующие файлы перепроверены.
UI: проверены 50 сценариев закреплений в Chromium/WebKit. В полном прогоне
48 прошли, два Chromium-сценария попали на холодную обработку модулей Vite и
перепроверены отдельно. Три сценария неверного сервера прошли в настоящей форме.
Геометрия и снимки списка проверены на ширинах 414 и 1280 px.

На Pixel прошли 28 UI-сценариев; 680 JVM-тестов Android, assemble и lint успешны.
Прежняя библиотечная test APK восстановлена с проверкой SHA-256.

Windows native updater: установка 1.6.100 → 1.6.101 сохранила синтетическую
сессию и черновик; неверная подпись отвергнута, повторное обновление не предлагается.
Отдельно на настоящем изолированном WebView проверены native IPC, DPAPI-копия,
восстановление входа/темы и refresh cookie после удаления cookie через CDP,
а также сохранение явного выхода. Рабочие протокол и автозапуск не изменены.

Для локального Vite ограничено наблюдение исходниками и ресурсами: временные
worktree, профили браузера и результаты не должны блокировать localhost:5173.
