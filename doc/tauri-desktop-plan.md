# Tauri desktop: план запуска и проверки

Дата начала: 2026-11-16. Первая целевая платформа — Windows (WebView2).

Цель: запустить SEP Chat в Tauri и проверить основные сценарии приложения.
Сборка и тесты с подменённым IPC не заменяют проверки на настоящем desktop.

## Текущий запрос: две зоны перетаскивания, 17 ноября

Работа перенесена в основной `chat_client`, ветка `main`. Прежняя ветка desktop
объединена с текущим main. Веб-версия повышена с 101 до 102.

- Для native drag и HTML drag внутри Tauri доступны «Загрузить файл» и
  «Загрузить фото/видео», если среди вложений есть фото или видео.
- Выбор зоны определяет формат отправки; физические координаты native события
  переводятся в CSS-координаты с учётом масштаба экрана. Обычные документы
  показывают одну зону, смешанные наборы сохраняют все вложения.
- Вход и выход overlay плавные (opacity/scale, 250 мс), подсветка зоны плавная;
  учтено системное уменьшение анимации. Во время чтения геометрия зон сохраняется.
- Прошли 13 E2E: фото/видео в обоих форматах при 200%, промежуточные кадры
  появления/исчезновения, HTML drop, смешанные вложения, браузерные DropZone и
  filechooser, native picker, исходные пути и смена чата во время чтения.
  Native IPC в этих E2E подменён; это не физическое перетаскивание из Проводника.
  TypeScript и ESLint изменённых компонентов прошли.
- [Снимок двух зон на тестовых данных](images/tauri-drop-zones.png).

По просьбе пользователя новая desktop-сборка и установка сейчас не выполняются.
Установленная 1.6.9 получит эти изменения только после следующей сборки.

## Профиль: версия и обновления по эталону, 17 ноября

- Эталон получен скриншотом из буфера обмена. Блок обновлений перенесён перед
  настройкой стикеров, как в Android-профиле.
- В раскрытом блоке слева показаны заголовок и описание без большой служебной
  иконки. Справа расположены «Обновить», процент с круглым индикатором,
  «Перезагрузить» либо галочка актуальной версии.
- Номер установленной версии теперь входит в описание состояния
  «Установлена новейшая версия», отдельного поля версии справа нет.
- Область прогресса имеет постоянную ширину: переход от неопределённой загрузки
  к 0–99% не двигает содержимое и не меняет высоту карточки.
- Прошли 9 E2E профиля: обе темы, ширина 280/391 px, масштаб 100/130%, все
  состояния updater, ошибки подписи и проверки, отложенная установка при звонке
  и передаче файлов. Новая desktop-сборка по просьбе пользователя не запускалась.

## Этапы

1. **Запуск и окружение** — dev-приложение запущено.
   - Проверить Rust, Bun, WebView2 и `bun run tauri:dev`.
   - Проверить авторизацию, восстановление сессии и доступность API/WebSocket.
   - Проверить отдельную production-сборку с локальными ресурсами.
2. **Окно и жизненный цикл**.
   - Трей, сворачивание, закрытие в трей, возврат и выход.
   - Разрешения IPC для управления окном и значком непрочитанного.
   - Повторный запуск, автозапуск и восстановление после сна/потери сети.
3. **Уведомления**.
   - Сообщение и входящий звонок при активном, свёрнутом и скрытом окне.
   - Клик открывает нужный чат/звонок; прочитанные уведомления удаляются.
   - Нет дублей с web push; учтены запрет уведомлений и настройки звука.
4. **Файлы и ссылки**.
   - Скачивание документа, фото, видео, записи звонка и нескольких файлов.
   - Сохранение в `Загрузки/SEP Chat`, русское имя, ошибки и крупные файлы.
   - Как в Android: скачать → прогресс → открыть локальный файл;
     «Показать в папке» и повторное скачивание после удаления с диска.
   - Скачивание не уводит окно с чата и не прерывает звонок.
   - Прикрепление, drag and drop, буфер обмена, внешние ссылки.
5. **Звонки**.
   - Разрешения и выбор микрофона/камеры, исходящий и входящий звонок.
   - Звук, видео, устройства, mute, завершение и повторное соединение.
   - Демонстрация экрана/окна, остановка, повторный запуск.
   - Работа при скрытом окне; возврат из уведомления.
6. **Проверки и выпуск**.
   - TypeScript, точечные unit/E2E, Rust check/test и desktop smoke.
   - Установленная Windows-сборка: уведомления, скачивания и звонок с двумя участниками.
   - Зафиксировать команды запуска, результаты и оставшиеся ограничения.

## Первичный аудит

- Tauri 2 уже интегрирован; есть трей, автозапуск и Windows toast.
- Dev URL: `http://localhost:5173`, frontend build: `build/`.
- Вложения используют браузерные ссылки/iframe; требуется проверка в WebView2.
- Управление окном из уведомлений использует IPC: требуется сверка capabilities.

## Результаты

### Выполнено 2026-11-16

- `bun run tauri:dev`: приложение скомпилировано и открыто в Windows.
  Пользователь выполнил вход; список чатов и история загрузились.
- Исправлены capabilities показа, фокуса и восстановления окна.
- Инициализация Windows-уведомлений больше не вызывает отсутствующий desktop API
  мобильного плагина. Очистка использует Windows toast history; удаление одного
  сообщения не удаляет уведомление входящего звонка.
- Добавлены нативные потоковые скачивания в `Загрузки/SEP Chat` без загрузки
  всего файла в память WebView. Имена не перезаписывают существующие файлы.
- Сведения о скачанном файле сохраняются в app data. Проверяются наличие и размер
  файла. При удалении или перемещении возвращается значок скачивания.
- Использованы существующие Android-состояния карточки: проверка, скачивание,
  прогресс, локальный файл, открытие. Статус обновляется при возврате в приложение.
- В меню сообщения и вложений профиля добавлено «Показать в папке».
- Медиаслайдер UI-kit и скачивание записей звонков используют тот же нативный
  механизм Tauri. Для текстовых экспортов и локальных файлов добавлено сохранение
  данных в `Загрузки/SEP Chat` с защитой от перезаписи существующих имён.
- В живом Tauri обнаружен строковый размер файла из API: перед IPC он теперь
  приводится к допустимому целому числу. Этот случай включён в E2E.
- Устранено мигание значка при возврате в приложение и открытии меню:
  фоновая проверка сохраняет известное состояние, одинаковый ответ не вызывает
  обновление карточки. Значок не скрывается при проверке или открытии файла;
  индикатор используется для настоящей загрузки. Добавлена проверка медленного IPC.
  Пользователь подтвердил в открытом Tauri: мигание исчезло.
- Защищённые файлы обращений сохраняют существующий web-сценарий проверки прав.
  Desktop-каталог отслеживает файлы, скачанные новым нативным механизмом;
  совпадение имени с произвольным файлом на диске не считается совпадением вложения.

### Подтверждённые проверки

- TypeScript (`bunx vue-tsc --noEmit`) и ESLint изменённых файлов.
- Production-сборка интерфейса (`bunx vite build`) завершилась успешно.
  Есть предупреждения Vite о размерах чанков и смешанных статических/динамических импортах.
- Актуальная production-сборка `bunx tauri build --no-bundle` завершилась успешно:
  `src-tauri/target/release/sep-chat.exe`, включая нативные скачивания,
  сохранение экспортов и single-instance. Интерфейс прошёл `vue-tsc` и собран
  штатным `bun run build`; сборка не требует Vite для запуска.
- Установщик NSIS собран командой `bunx tauri bundle --bundles nsis --ci`:
  `src-tauri/target/release/bundle/nsis/SEP Chat_1.6.0_x64-setup.exe`
  (размер зависит от последней сборки). Во время упаковки
  приложение должно быть остановлено:
  Windows блокирует изменение работающего exe.
- Проверен запуск актуального release exe с локальным адресом
  `http://tauri.localhost/`. Старое сохранённое состояние показалось до проверки
  авторизации, затем открылся экран входа. В установленном release выполнен вход
  в разрешённый аккаунт; загрузились актуальные чаты и последнее тестовое вложение.
  При первом запуске наблюдался запрос геолокации телеметрии; разрешение
  автоматически не выдавалось.

  `%LOCALAPPDATA%/SEP Chat` виртуализировался, а созданный ярлык указывал на

  `C:/Users/edgar/Applications/SEP Chat`; ярлык рабочего стола указывает на

  причина менять стандартную папку NSIS для всех пользователей.
  Установленный exe обновлён последней сборкой; совпадение с исходным release
  подтверждено SHA-256. Проверен повторный запуск актуального установленного exe.
- 18 E2E файлов: переходы состояний Tauri-файла, папка и удаление;
  Android-открытие PDF и защита от повторных кликов; скачивания во время звонка;
  оригиналы HEIC, видео, PDF и нативный мост Tauri из настоящего компонента слайдера.
  Отдельно прошёл E2E desktop IPC уведомлений.
- 18 unit-проверок состояний файла, фоновой перепроверки и URL загрузки.
- 5 Rust-проверок: имена, идентичность URL, настоящие HTTP-скачивание и запись
  на диск, повторное использование без сети, удаление, 404 и неверный размер.
  Проверены байты локального экспорта, коллизии имён и некорректные данные.
  Команда: `cargo test --manifest-path src-tauri/Cargo.toml --test desktop_files`.
  Перед запуском на Windows остановить dev-приложение: Cargo также пересобирает

- Для Windows-тестового exe добавлен манифест Common Controls 6;
  манифест приложения остаётся под управлением Tauri.

  файл `Проверка Tauri.txt` (113 байт), отправлен в собственное «Избранное»
  и скачан обратно в `Загрузки/SEP Chat`. Значок сменился со скачивания
  на открытие; SHA-256 исходника и скачанной копии совпал.
  Нажатие на локальную карточку открыло файл в Блокноте, текст проверен.
  Для системного диалога инструмент потребовал клавиатурный ввод пути:
  координатный ввод в дочернее окно WebView2 отклонялся.
- Добавлен `tauri-plugin-single-instance`: повторный запуск возвращает существующее
  окно. В настоящем Windows-приложении подтверждены один постоянный процесс,
  тот же дескриптор окна после повторного запуска, закрытие `Alt+F4` в трей
  с сохранением процесса и возврат того же окна повторным запуском.

  с аргументом также проверен ниже.
- При живом первом запуске release обнаружена зависимость регистрации
  уведомлений от ответа на запрос геолокации. Для Tauri ожидание убрано:
  геолокация и уведомления инициализируются независимо. Новый E2E запускает
  настоящий корневой компонент с локальным сервером, оставляет геолокацию
  без ответа и проверяет готовность обработчика уведомлений. Оба desktop E2E
  уведомлений прошли. TypeScript и ESLint корневого компонента прошли;
  production exe пересобран с этой правкой. Разрешения геолокации автоматически
  не менялись.

- На прежней установленной версии повторный экран входа воспроизведён примерно
  после истечения access token. Нативный транспорт исправлен и проверен в WebView2,
  но длительная production-сессия и автоматический refresh новой установленной
  версии требуют отдельного прогона.

Непроверенные сценарии не считаются рабочими только на основании компиляции.
