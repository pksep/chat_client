# Локальная проверка сохранения телеметрии

Из папки `chat_client`:

```powershell
bun run test:telemetry:local
```

Нужны запущенный Docker Desktop, Node.js, зависимости (`bun install` в `chat_client` и соседнем `chat_server`) и Chromium для Playwright. Если браузер ещё не установлен: `bun x playwright install chromium`. При первом запуске Docker скачает `grafana/loki:3.5.0`.

Команда сама поднимает отдельный Loki с дисковым томом, локальный Nest API с настоящим `TelemetryModule`, Vite и браузер. Уже запущенный сервер разработки продолжает работать отдельно. База данных, серверная production-конфигурация и рабочая учётная запись не нужны. Тестовые сервисы слушают только loopback и используют свободные порты.

## Что проверяется

- Клиент отправляет событие сообщения и координаты с одним `trace_id`; сервер добавляет страну и город по IP, сохраняя координаты устройства.
- Локация включена по умолчанию и не требует чекбокса. Системное разрешение запрашивается при первом открытии приложения (в браузере — после показа первого экрана); при отправке сообщений запрос не появляется. Координаты появляются после разрешения; его отзыв удаляет их из ожидающих отправки событий.
- В APK Android геолокация входит в нативный стартовый запрос вместе с остальными доступами. Клиент ждёт его завершения перед чтением координат; повторный диалог через Capacitor не открывается. Уже выданного приблизительного доступа достаточно.
- Настоящий компонент списка чатов записывает расхождение `WAIT`/`READ`, отдельную ручную метку непрочитанного и `WAIT`, который не исчез за 30 секунд.
- Настоящий обработчик обновления записывает ошибку запуска с кодом и таймаут отсутствия прогресса. События каждой попытки связаны своим `trace_id`.
- Проверка читает события через Loki Query API, затем останавливает и запускает Loki и сравнивает содержимое записей по ID. Успешный HTTP-ответ сам по себе не считается подтверждением сохранения.

Используются тестовый forwarded IP `81.2.69.142`, координаты браузера `40.18, 44.51` и эмуляция ответов Android/RuStore. Это проверяет сбор и сохранение диагностик; реальный GPS телефона и скачивание APK проверяются на устройстве отдельно. Для обычного `localhost` город определить нельзя — ожидается `status=unavailable`.

## Как посмотреть сохранённое

В конце команда выводит путь `test-results/telemetry-local/<запуск>/`:

- `report.json`: итог `status=passed`, число записей и `storageRestartVerified=true`.
- `events.jsonl`: настоящие записи, прочитанные из Loki **после перезапуска**. Одна JSON-запись на строку.
- `events-before-restart.jsonl`: записи до перезапуска для сравнения.
- `server.log`, `loki.log`, `playwright/`: диагностика, если проверка не прошла.

В событиях сообщения смотрите `context.location.ip` и `context.location.device`; в диагностике чатов и обновлений — `event_name`, `trace_id` и `payload`.

Чтобы вывести события сообщения из последнего запуска в PowerShell:

```powershell
$run = Get-ChildItem test-results/telemetry-local -Directory |
  Sort-Object LastWriteTime -Descending | Select-Object -First 1
Get-Content (Join-Path $run.FullName 'events.jsonl') |
  ConvertFrom-Json |
  Where-Object event_name -eq 'chat.message_send.location' |
  ConvertTo-Json -Depth 12
```

Отрицательная проба специально отправляет одно событие при остановленном Loki. Текущий API возвращает `accepted=1`, хотя запись не сохранилась; отчёт фиксирует `unavailableStorageProbe.stored=false`. Поэтому основная проверка требует прочитать сами записи из хранилища. Это также показывает текущее ограничение: ответ `accepted` означает приём пакета API, а не гарантию доставки в Loki.

После проверки тестовые контейнер и том удаляются. Экспорт событий и отчёт остаются на диске, исключены из Git и не требуют коммита.
