# Загрузка списка чатов

Основной путь повторного запуска — подтверждённый снимок из IndexedDB и
`GET /topics/sync?version=1&pts=…&syncedAt=…`. Курсор списка независим от
`pts:last` WebSocket: получение события ещё не означает сохранение всех его
изменений на диске.

Подтверждённые карточки и курсор сохраняются одной записью
`<userId>:topics-sync` в `chat-offline-state-db/entities`. Обычный изменяемый кеш
`<userId>:topics` и быстрый кеш localStorage не могут продвинуть этот курсор.
Это также защищает снимок от фоновых записей другой вкладки.
Офлайн-интерфейс использует последние локальные данные. Дельта всегда
накладывается на отдельный подтверждённый снимок, прочитанный вместе с курсором.

Сервер возвращает изменённые карточки, актуальный список ID доступных обычных
чатов, краткую сводку непрочитанных и текущие активные звонки. Состав сверяется
отдельно от PTS: после исключения пользователя из группы replay по текущим
членствам может уже не вернуть ему событие удаления. Личные настройки,
участники и профили дополнительно проверяются по времени изменения, поскольку
не все такие изменения пока записываются в журнал PTS.

Клиент применяет дельту только при совместимой версии и наличии всех карточек
из списка ID в снимке или ответе. Чаты, к которым пропал доступ, удаляются из
основного списка. События WebSocket продолжают обслуживать текущую сессию.

Начальная пагинация `GET /topics?page=1&limit=50&scope=chats&includeUnread=true&includeSync=true`
нужна при первом входе, неполном/повреждённом кеше, несовместимой версии,
очищенной истории PTS, курсоре старше 30 дней или более 100 изменённых чатах.
Сбой дельты также приводит к попытке начальной загрузки. Следующие страницы
загружаются при прокрутке; курсор подтверждается только после последней.
Начальный курсор снимается сервером до чтения первой страницы, чтобы изменения
во время пагинации попали в следующую синхронизацию.

Служебные чаты звонков и обращения клиентов исключаются сервером до пагинации
основного списка. Раздел клиентов и фоновые снимки используют свои scopes.
Старый сервер может игнорировать `scope` и не возвращать `sync`. Если его первая
страница содержит служебные топики, клиент продолжает пагинацию до 50 обычных
чатов или конца списка, запрашивая не более трёх страниц одновременно. Служебные
карточки не попадают в основной кеш. Иначе первая страница звонков оставляет главный экран
пустым. Без серверного протокола клиент не подтверждает PTS-курсор списка.
Для перехода в конкретный чат без локальной карточки остаётся точечный GET.
При холодном запуске Android начинает свежие запросы пользователей и списка
параллельно с созданием WebView. В SharedPreferences сохраняется только план
относительных URL для следующего запуска, привязанный к пользователю и серверу.
Для подтверждённого снимка это `/topics/sync` с его курсором; для старого API —
страницы обычной пагинации. Токен берётся из существующей нативной сессии.
JavaScript однократно забирает ответы тех же запросов через мост, не повторяя HTTP.
Ранний стартовый модуль начинает передачу ответов до загрузки Vue и фоновых
native-плагинов. SDK потребляет готовый пакет из памяти; неприменимые или
отсутствующие ответы получают обычным путём. Пакет проверяется по исходному
токену, серверу и времени начала запроса и удаляется после инициализации.
В пакет входят только завершённые запросы: медленная дополнительная страница
не задерживает готовые ответы. Незавершённый запрос остаётся доступен SDK отдельно.
Ответ другого сервера/токена, старше 10 секунд или предшествующий новому событию
топика не применяется; обычный HTTP остаётся запасным путём с общим таймаутом.
Прочтение и реакции отменяют только страницу соответствующего топика старого
API. Другие готовые страницы используются без повторного HTTP. Изменение состава
или порядка списка, дельта PTS и общая сводка непрочитанных сохраняют полную
проверку свежести. Причина отклонения отмечается без пользовательских данных.
Запоздалый ответ пользователей сохраняет более свежие изменения WebSocket,
включая события до запуска JavaScript-запроса. Для уведомления отдельно сохраняется
ранняя загрузка истории выбранного чата. Старый фоновый снимок карточек не может
перезаписать уже применённый сетевой результат.

На телефоне стартовый скелетон ждёт применения сетевого результата списка и
обновления справочника пользователей, а также готовности выбранной переписки.
На главной мобильный список монтируется один раз после этой сверки, чтобы
повторные скрытые отрисовки не занимали поток перед обработкой свежих ответов.
Старый API без курсора и без подтверждённого снимка не записывает пустой PTS-снимок
при каждом открытии; если прежний курсор существует, он по-прежнему сбрасывается.
Системная кнопка «Назад» на главном экране сворачивает Android-приложение через
`App.minimizeApp`, сохраняя Activity и WebView. Возврат из фона использует обычную
сверку соединения и данных; холодный запуск остаётся нужен после выгрузки процесса.
Нативный логотип снимается раньше, когда WebView подготовил стартовый экран:
ожидание сети остаётся за скелетоном. При ошибке/таймауте открывается доступный кеш
со статусом ошибки; бесконечного ожидания сети нет.

Справочник загружается по всем страницам и хранит исходные ID скрытых дубликатов:
старые чаты могут ссылаться на них. Запоздалый HTTP не перезаписывает WS-обновление,
пришедшее после начала запроса. Отсутствующее `lastOnline` не означает онлайн;
кешированный `null` требует подтверждения в текущем подключении. Частичное
обновление статуса без `lastOnline` сохраняет прежнее время посещения.
Гонки HTTP/WS проверяются отдельно для статуса и присутствия: частичное событие
одного поля не отменяет свежий ответ другого.

Проверки: `e2e/topic-sync.spec.ts`, `e2e/topic-pagination.spec.ts`,
`e2e/startup-freshness.spec.ts`, `e2e/favorite-refresh.spec.ts` и серверные
`topics.service.spec.ts`.
