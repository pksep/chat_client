# Автоматическое обновление веб-чата

Версия работающей сборки встраивается из `public/web-update.json` при сборке.
Серверная версия проверяется без HTTP-кэша раз в минуту в активной вкладке,
а также при возвращении к ней и восстановлении сети. Для новой выкладки нужно
увеличить `version` до сборки приложения.

В `localStorage.chat_web_update_day` сохраняется локальная календарная дата
первого запуска механизма и последующего автоматического обновления. Если день
отличается и серверная версия новее работающей сборки, вкладка обновляется
автоматически. Смена дня без новой версии не вызывает перезагрузку. Дата
сравнивается по часовому поясу устройства; уже открытые вкладки также сохраняют
собственное состояние, чтобы обновление одной вкладки не скрывало обновление другой.

Перед переходом проверяется доступность HTML. Сбрасывается Workbox-кэш оболочки,
удаляется регистрация старого `/sw.js`, затем загружается URL с параметром обхода
кэша. После запуска параметр убирается, маршрут и остальные параметры сохраняются.
Авторизация, IndexedDB, медиа-кэши и service worker уведомлений сохраняются.

Обновление откладывается в скрытой вкладке, офлайн, во время звонка, загрузки
вложения и редактирования непустого поля. Ошибка проверки оставляет вкладку
работающей до повторной попытки. Метка в sessionStorage предотвращает повтор
одной попытки за тот же день. Автоматический переход записывает событие
`app.update.web.auto_reload` с исходной и целевой версиями.

Веб-кнопка «Обновить чат» больше не показывается. Capacitor и Tauri используют
прежние механизмы обновления.

Проверка: `bun run test:e2e e2e/web-daily-update.spec.ts e2e/menu-update.spec.ts e2e/rustore-menu-update.spec.ts`.
