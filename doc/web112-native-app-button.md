# Веб 112: одна кнопка приложения, PWA только на iOS

В desktop-меню осталась одна основная кнопка «Открыть приложение». Кнопка
использует `sepchat://open` и оформление основного действия проекта.
Отдельной кнопки скачивания рядом нет; свёрнутое меню показывает одну иконку.

Браузер не предоставляет надёжного API для проверки установки обычного Tauri.
Поэтому кнопка сначала передаёт управление обработчику протокола. Если окно
потеряло фокус или вкладка скрылась, предложение скачивания не показывается.
Если вкладка остаётся активной, через две секунды та же кнопка предлагает
скачивание и раскрывает ссылки Windows, Mac Apple Silicon, Mac Intel и Linux.
Таймер не считается доказательством отсутствия приложения; текст предлагает
установщик условно: «Если приложение не открылось…». Автоматического скачивания
и скрытого запроса запуска приложения при загрузке страницы нет.

PWA сохранена для iPhone/iPad: manifest подключается динамически только
в iOS-браузере. Остаются инструкции добавления на экран «Домой», iOS-оформление
и Apple push. Desktop/Android HTML не подключает manifest; событие установки
браузерного приложения подавляется. `installIOS` не показывает инструкцию
на остальных платформах. Старый Workbox worker и его precache удаляются вне
iOS; push/upload workers, авторизация и кэш пользовательских файлов сохраняются.

Проверки: сценарии одной кнопки и четырёх установщиков в Chromium/WebKit,
основное меню, обе темы, свёрнутое меню, отсутствие desktop-кнопки на мобильном,
подключение manifest только на iOS, сохранение Apple push и инструкции установки.
Production HTML дополнительно проверен в отдельных Windows/Mac/Android/iPhone
контекстах: 0/0/0/1 manifest соответственно. Полная production-сборка прошла.

Исправление локального обработчика `sepchat` и изоляция QA описаны отдельно:
[desktop-protocol-repair-2026-11-20.md](desktop-protocol-repair-2026-11-20.md).
Нативный NSIS-тест подтвердил, что установка, обновление и удаление QA теперь
сохраняют рабочие протокол и автозапуск пользователя.
